## 1. Focus ring on text fields

The cause was a single blanket rule in [base.css:44](src/styles/tokens/base.css:44):

```css
:focus-visible { outline: none; box-shadow: var(--ring-focus); }
```

The subtlety is that **a mouse click on a text field does match `:focus-visible`** — that's per spec, unlike a click on a button. So that one rule was drawing a ring on every click into every input and textarea in the app. I confirmed it on the live page: `matchesFocusVisible: true` on a plain click.

Fixed at the root so it covers every text field at once, including ones I didn't write:

```css
:is(textarea, [contenteditable="true"], input:not([type="button"], [type="checkbox"], …)):focus-visible {
  box-shadow: none;
}
```

I verified the selector is surgical rather than just deleting focus indication:

| | ring suppressed |
|---|---|
| text / search / untyped input, textarea, contenteditable | ✅ yes |
| checkbox, radio, range, submit, button, links | ❌ no — keeps its ring |

Two components also added their own ring via Tailwind utilities, which sit in a later cascade layer and would have survived the base fix — so [textarea.tsx](src/components/forms/textarea.tsx) and [input.tsx](src/components/forms/input.tsx) now light their **border** on focus instead of ringing. That keeps a visible focus affordance for keyboard users while removing what you objected to.

On a real click the prompt now reports `boxShadow: none` — just a caret.

## The state split

This is the part worth looking at. *Which* jobs this session started is client state and lives in `useState`. *What each job produced* is server state and lives in React Query — **one query per job** via `useQueries`, so each image resolves on its own clock rather than the batch appearing at once. The feed's cells are derived from both on every render, so there's no second copy of the truth to drift.

Each job gets its own staggered server deadline, and its query stops polling the instant it lands.
