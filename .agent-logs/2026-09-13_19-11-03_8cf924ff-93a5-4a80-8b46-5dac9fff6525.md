Here's the design. Four sections — tell me if any part is wrong and I'll revise before writing the spec.

## 1. Shell and route

`/audio` as a new `(studio)` segment, so it inherits `StudioLayout` (the `bg-q-page` ground, `QueryProvider`, no page scroll). Grid differs from the video studio in one measured way:

| | Video studio | Audio (measured) |
|---|---|---|
| Columns | `md:grid-cols-[20rem_1fr]` | `grid-cols-[max-content_1fr]`, aside `w-85.5` = **342px** |
| Panel radius | `rounded-q-500` (20px) | `rounded-3xl` = **24px** → `rounded-q-600` |
| Pane | card w/ dot grid | **no card** — toolbar floats `absolute` over a scroller inset `left-6` |

Below `md`, the live site swaps to a **full-screen sheet**: "CREATE AUDIO" header with a close button, no right pane, and the batch stepper moves out of its row into the CTA footer beside Generate.

## 2. The three forms

One panel, three tab-swapped bodies, sharing a control vocabulary that's almost entirely primitives we already have (`DropZone`, `QPopover`, `BatchStepper`, `GenerateButton`):

- **Text to Speech** — upload zone (*Optional*, ≤3 voices/audios or image) → Script editor (`@`-mentions the attachments) → Model row → Batch `1/4` → Voice details (*Optional*, 0/500) → Advanced settings → Generate
- **Voice Change** — "Pick a voice" + "Add your clip", both ***Required***. Nothing else.
- **Translate** — "Add your clip" (*Required*) + Language row. Nothing else.

**Advanced settings** (TTS only) expands inline: an Expression intensity fill-slider, a Mood gradient fader (Angry↔Neutral↔Happy), Speed/Pitch/Volume as a 3-up row of popover buttons, Output format, Sample rate, and a Save settings switch.

Schema is one discriminated union on `mode`, keyed the way `PendingRequest` already discriminates on `kind`. Files project to metadata through `toAudioRequest()`, exactly as `toVideoRequest()` does — a `File` doesn't survive `JSON.stringify`.

## 3. Pipeline

Audio drops into the existing seams rather than opening new ones — the types already reserve the slot:

- `GenerationKind` already includes `"audio"`; `PendingRequest` gets its third arm
- `generation-jobs.server.ts` gets an `'a'` id tag alongside `g` and `v`, reusing the stateless deadline-in-the-id trick
- `GenerationAsset` gains `duration?: number` — a waveform tile has to reserve its width before the file loads, the same reason `w`/`h` exist for images
- The store, polling, and the signed-out **hold-request → auth → auto-resume** flow are reused untouched

Two things genuinely new: **`--q-bg-section: #18191c`** (the how-it-works cards; `--q-bg-plan` is already this exact value, so it becomes the alias) and five type ramps the audio page uses that the `q-` layer doesn't have yet — notably the 40/48/−1.6px display and the 18/24/−0.4px CTA label.

## 4. Two calls I'd make, flagging them rather than burying them

**Waveform bars derived from the job id**, not `decodeAudioData`. Fixtures are cross-origin, so a real decode is one CORS header away from a permanently empty tile — and deriving from the id is the trick `generation-jobs.server.ts` already uses to stay stateless.

**Our own credit formula.** Theirs isn't linear in characters (13 chars → 0.1, 17 → 0.3 on the same model), and I'd rather write down `rate(model) × batch` in `config/audio.ts` than ship a guess that's wrong in a way nobody can check.
