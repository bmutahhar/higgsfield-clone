## What the live site actually does

I measured it rather than eyeballing — it toggles `data-header-compact` on `<html>` and drives every size from CSS:

| | at rest | scrolled |
|---|---|---|
| bar height | 52px | 36px |
| logo | 32px | 20px |
| right-side buttons | h36, radius 10, 0 12px | h24, radius 8, 0 10px |
| nav links | 28px / 14px — unchanged | same |

Trigger is ~9px of scroll (I stepped `scrollY` a pixel at a time against the attribute) — effectively "the moment the page moves". Both sizes cross in `300ms ease-in-out`.

## What I built

- **[use-compact-header.ts](src/components/marketing/use-compact-header.ts)** — toggles `data-compact` on the header. It writes straight to the DOM instead of `useState`: every size is a utility keyed off the attribute, so React state would re-render the whole nav on a scroll frame for nothing. Passive listener, coalesced onto one rAF.
- **[site-header.tsx](src/components/marketing/site-header.tsx)** — `data-compact:h-9` on the bar, `group-data-compact:*` on the logo and buttons. All Tailwind, no inline styles, no state.
- **[(marketing)/layout.tsx](src/app/(marketing)/layout.tsx)** — one `data-page-scroll` attribute marking the group's scroll container.

That last one was needed because the shell changed underneath me mid-task: another session moved the header into the root layout and made the body non-scrolling, so `window.scrollY` is now always 0. The hook watches the marked container and rebinds on navigation. Studio routes mark nothing and correctly stay at the resting size.

One deliberate divergence: the live bar overlays a scrolling document, so its 16px just vanishes. Here the header is chrome above a separate scroll container, so it hands those 16px back to the content area — both animate together.
