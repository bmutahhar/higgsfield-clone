Fixed. The cause wasn't where the symptom pointed.

## Root cause

`store.server.ts` held the user database in a module-level `const users = new Map()`. Next gives route handlers and server components **separate module graphs**, so that module was instantiated twice — two independent Maps.

Both copies seed the mock user at import. But anyone who signs in at runtime is created by a *route handler*, so their record lands in the handler's Map only. The server-component render that paints the header reads the other one and sees nobody.

That's why `/api/auth/me` and the page disagreed about the same cookie.

**The discriminating test** — same cookie mechanism, same signature, same `readSession`, only the user differs:

| user | `/api/auth/me` (handler) | page render (RSC) |
|---|---|---|
| `user_1` — seeded at import, in *both* Maps | found | signed-**in** |
| `user_2` — created at runtime by a handler | found | signed-**out** |

## The fix

The store now hangs off `globalThis`, the one object both graphs share. `nextId` moved in with it, or the two graphs would mint colliding ids.

One subtlety worth naming: the import-time `resetStore()` had to become *seed only if empty*. Left unconditional against a shared store, the second graph to load would wipe every account the first had taken — the same bug in a different costume. `resetStore()` itself still truly resets, because the tests depend on that.
